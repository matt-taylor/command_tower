# Upgrade: CommandTower 0.25.0 (draft)

**From:** `0.24.0`  
**To:** `0.25.0`

Draft. Logins now start a device session; tokens carry a `sid` and the session row decides expiry. See [authentication](../authentication.md#device-sessions).

## Host-visible changes

| Change | Host impact |
|--------|-------------|
| Migration `CreateCommandTowerDeviceSessions` | New table `command_tower_device_sessions` with a foreign key to `users`. Additive and reversible. |
| `config.session.*` | `idle_timeout` (30 days), `absolute_timeout` (90 days), `last_seen_write_interval` (5 minutes), `enforce` (ENV `COMMAND_TOWER_SESSION_ENFORCE`), `upgrade_legacy_tokens` (ENV `COMMAND_TOWER_SESSION_UPGRADE_LEGACY_TOKENS`, not yet acted on). |
| New 401 codes | `session_expired` and `session_revoked` use the envelope `{ "data": null, "errors": [{ "code", "message" }] }`. Other 401 bodies are unchanged. |
| Session tokens outlive `jwt.ttl` | A token with `sid` is valid until the session's idle or absolute limit, not 7 days. Sid-less tokens keep the old rule. |
| Refresh header | `X-Authorization-With-Reset` is emitted only for bearer-sourced requests, at most once. Cookie-sourced refreshes set the cookie only. |
| Inclusive length bounds | `password_length_min/max` and `email_length_min/max` are now inclusive. Defaults change to password 8–64 and email 3–254 (email was 8–64 exclusive, so 9–63). A host that set explicit values should re-check them; `GET /auth/identity-policy` now serves the configured values unadjusted. |
| Common-password blocklist | Register, password reset and `PATCH /me/password` reject passwords in the bundled top-100k list. Override with `config.login.plain_text.password_blocklist_paths`. |
| Email rules | `User` normalizes `email` (strip, downcase) and validates format and length on change. |
| Identity policy v2 | `GET /auth/identity-policy` adds `maxBytes`, `passwordRules`, `rules` (`{ id, label, check }`) and username `selfService` / `selfChange` / `prompt` (`config.username.self_service`, `self_change`, `prompt`). Existing keys are unchanged. |
| `POST /auth/password-check` | New public route, 60 per minute per IP. See [api_reference](../api_reference.md#post-authpassword-check). |
| `POST /auth/register` | Needs only `email` and `password`; optional `start_session: true` returns a login-shaped session (`tokenExpiresAt`, `token` unless the cookie-mode web rule omits it). The six-field body still works. Policy failures add `passwordRulesFailed`; an existing email answers with a friendly message; a per-email bucket (`config.login.rate_limits.register_attempts_per_email`, default 5 per hour, `0` disables) and `retry_after_seconds` on `signup_ip_rate_limited` are new. |
| Optional password confirmation | `POST /auth/password-reset/reset` and `PATCH /me/password` accept a request without `passwordConfirmation`; when sent it must still match. |
| Deprecated endpoints | `signup-session`, `password-recovery-session`, `email/availability`, `username/availability`, the `Signup` / `Recovery` authorization schemes, the old register shape and valid sid-less tokens each emit `command_tower.auth.legacy_contract_used` (payload: `endpoint`, `app_version`, `platform`; observation only, responses unchanged). Use it to decide when old clients are gone. |
| Client compatibility contract | `auth.device_session` is seeded in the client-compatibility registry (observe mode, inert until the host binds per-platform minimums). |
| Email rake tasks | `command_tower:users:email_duplicates` (read-only report, includes blank emails), `command_tower:users:add_email_unique_index` (skips with a warning and an `email_unique_index_skipped` event when duplicates exist) and `command_tower:users:normalize_emails` (`DRY_RUN=1` to only report; skips collisions). No migration ships; run these on the host database. |
| One extra read per request | Authenticating a `sid` token reads one `command_tower_device_sessions` row, plus at most one `last_seen_at` write per interval. |

## Host seams

- `CommandTower::Jwt::LoginCreate.call(user:, impersonation_session_id: nil, device_session: nil)`: the optional `device_session:` adds the `sid` claim. Hosts that call or wrap it to mint tokens should use `Services::Auth::IssueSession` so a session exists.
- `CommandTower::Jwt::AuthenticateUser` returns an `AuthenticationOutcome` with new `code` and `device_session` readers. `AuthContext` gains `device_session` and `legacy_token`.
- Plain-text login now issues its token through `IssueSession`.

## Host actions

1. Bump the gem and run `db:migrate` before the new code serves traffic.
2. Check host clients and proxies that treat any 401 the same: two new 401 codes now exist.
3. If the host reads `X-Authorization-With-Reset` on cookie requests, switch to the cookie.
4. Kill switch: set `COMMAND_TOWER_SESSION_ENFORCE=false` to skip revoked and idle checks without a deploy.
5. Set `config.session.omit_body_token_min_app_version` for the host (or `COMMAND_TOWER_SESSION_OMIT_BODY_TOKEN=false`) **before** upgrading. The gem default is `"0.4.0"` and is compared with the host app's `X-App-Version`, not the frontend package version. A host app above `0.4.0` (DoubleFloor Me is `1.0.0`) otherwise gets the body token omitted for every web client on upgrade. Set it to the first app version whose web client works from the cookie alone. See [authentication](../authentication.md#body-token-omission-host-obligation).

## Rolling deploy

Migrate first, then roll. Old nodes mint sid-less tokens, which new nodes accept under the old rule. New-node tokens carry `sid`; an old node ignores that claim and applies `jwt.ttl`.

## Not in this release

- Logout, revoke-all and purge of ended sessions.
- Installation-id capture and legacy token upgrade.
