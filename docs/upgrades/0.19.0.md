# Upgrade: CommandTower 0.19.0

**From:** `0.18.0`  
**To:** `0.19.0`

Minor release: how a push presents itself, and Expo ticket and receipt facts. Notification types can declare badge eligibility, urgency, sound, and a required deep link. Preferences can store urgency and sound. Expo send records provider metadata, and the existing recovery job collects receipts afterward. Two new migrations.

## Host-visible changes

| Change | Host impact |
|--------|-------------|
| Notification type declaration | Optional `badge_eligible` (default false), `urgency`, `sound`, and `deep_link_required` (default false). Omitted urgency and sound stay fixed at `normal` and `default`. |
| `config.messaging.sounds` | Host entries `{ id:, label:, asset: }` appended after System Default (`id: "default"`, no asset). Asset names end in `.wav`, `.aiff`, or `.caf`. Invalid catalogs fail registry seal. |
| `config.messaging.expo.home_deep_link` | String or zero-argument Proc. Required when a push-capable type is registered and the Expo adapter is not `disabled`. Used when a push has no metadata `deep_link` and no live inbox item. |
| `config.messaging.expo.self_test_deep_link` | String or zero-argument Proc. Resolved when `POST /me/push/test` runs. Blank fails the test before Produce. |
| `config.messaging.expo.interruption_levels` | Subset of `normal`, `time_sensitive`, `critical`. Default is `["normal"]`. A declared urgency above this set degrades `critical` → `time_sensitive` → `normal`. |
| Produce `metadata.deep_link` | Required when the type sets `deep_link_required` and the value is missing. Push-capable types that are not inbox-backed should set that flag. |
| Preferences | `GET` catalog entries include `urgency` and `sound`. `PATCH` accepts `preferences.urgency` and `preferences.sound` alongside inbox and channels. |
| Inbox unread | `Messaging::Inbox.unread_count` returns `count` and `badge_count`. `badge_count` is unread items whose type is badge-eligible. Expo `badge` is sent only for those types, including `0`. |
| Push thread | A communication with `conversation_key` sends that key as the push thread id. |
| Delivery attempts | Nullable `provider_metadata` JSON stores Expo ticket and receipt facts. `finished_at` is indexed for receipt collection. |
| Recovery | After the existing redrive, receipt collection runs. A collection error is logged and does not fail the redrive. |

## Host actions

1. Bump gem to `0.19.0` (or `>= 0.19.0`).
2. Install and migrate:
   - `bundle exec rails command_tower:install:migrations`
   - `bundle exec rails db:migrate`
   - New files: `20261012000001_add_provider_metadata_to_messaging_delivery_attempts`, `20261012000002_add_finished_at_index_to_messaging_delivery_attempts`.
3. If Expo is not `disabled` and any type allows push, set `config.messaging.expo.home_deep_link`. Registry seal raises without it.
4. Set `self_test_deep_link` before members use push self-test.
5. Add `time_sensitive` to `interruption_levels` only after the shipped iOS binary has the Time Sensitive capability. Leave `critical` off unless Apple granted Critical Alerts.
6. Existing declarations that omit the new fields keep today's behavior: no badge, fixed normal urgency, System Default sound, deep link not required.

## Not in this release

- No host notification types. Hosts still register their own keys.
- No bundled custom sound files. The catalog stores the asset name. The app binary supplies the file.
- No backfill of `provider_metadata`. Existing attempts stay null.
