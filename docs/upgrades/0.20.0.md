# Upgrade: CommandTower 0.20.0

**From:** `0.19.0`  
**To:** `0.20.0`

Minor release: push delivery certainty — persist Expo ticket metadata reliably on MariaDB and stop duplicate Expo sends when submission is uncertain. Email retry policy and Inbox behavior are unchanged.

## Host-visible changes

| Change | Host impact |
|--------|-------------|
| `DeliveryAttempt#provider_metadata` | JSON attribute caster (MariaDB LONGTEXT / `json_valid`). Accepted Expo ticket metadata persists on success and retryable non-submission paths. |
| Push execution recovery | Push-only duplicate-averse policy: at most one automatic retry when a finished attempt recorded `submission: not_submitted`. Uncertain outcomes (`submission_uncertain`), accepted tickets, and open `started` attempts without proof terminalize without another Expo POST. Push claim budget `PUSH_RETRY_LIMIT` = 2. Email keeps grace window and `MAX_ATTEMPTS` = 5. |
| `DeliverWorkflow` | Pre-send guard blocks Expo when prior push state does not allow another submission. |
| Expo adapter | Classifies pre-request failures as `not_submitted` (retryable once); post-dispatch uncertainty is terminal. |
| Observability | `messaging.execution.attempt.finalize_unpersisted` when attempt finalization cannot be persisted (diagnostic). |

## Host actions

1. Bump gem to `0.20.0` (or `>= 0.20.0`).
2. **No new migration.** Run `bundle exec rails db:migrate` only if other pending host migrations exist.
3. After deploy, legacy push rows with `started` attempts and null metadata are terminalized on the next recovery pass (no data repair script).

## Not in this release

- No Inbox document or rendering changes.
- No email adapter or email retry cap changes.
- No new HTTP routes or workflows.
- No automatic backfill of historical `provider_metadata`.
