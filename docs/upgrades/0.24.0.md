# Upgrade: CommandTower 0.24.0

**From:** `0.23.0`  
**To:** `0.24.0`

Minor release: Home Notices. A host registers `Campaign` and `Delivery` notices that appear once for a signed-in user as a blocking takeover or a dismissible card. Authoring, selection, pacing, events and the kill switch runbook: [Home Notices](../home_notices.md). Everything is off by default (`config.home_notices.enabled` is false), so a host that changes nothing sees no behavior change except the additions listed below.

## Host-visible additions

| Change | Host impact |
|--------|-------------|
| Migration `CreateCommandTowerHomeNotices` | Creates `command_tower_home_notices` (one row per user and notice) with indexes. Additive and reversible. |
| Migration `CreateCommandTowerHomeNoticeControls` | Creates `command_tower_home_notice_controls` (kill switch rows, keyed by notice key). Additive and reversible. |
| `config.home_notices` | `enabled` (false), `notices` (`[]`), `global_cooldown` (8 hours, at least 1 hour), `blocking_daily_cap` (2), `max_open_deliveries` (20), `rate_limit_per_minute` (30), `mutation_rate_limit_per_minute` (120), `update_app_campaign` (true). Invalid values fail the boot check. |
| Routes | `GET /me/home-notices`, `POST /me/home-notices/:id/impression`, `.../acknowledge`, `.../dismiss`, and `PATCH /admin/home-notices/:key`. All are routed only when `config.home_notices.enabled`; otherwise 404. See [API reference](../api_reference.md#home-notices). |
| Entity `me_home_notices` | Needed for the four `/me` routes. Also a seeded principal capability, so clients gate on `GET /auth/principal-capabilities`. |
| Entity `admin_home_notices_kill` | Needed for the kill switch. Not a principal capability. |
| Audit events | `home_notice_impression`, `home_notice_acknowledged`, `home_notice_dismissed`, `home_notice_control_changed`. See [Audit](../audit.md). |
| Instrumentation events | Category `home_notices`: `selected`, `controls_unavailable`, `period_key_failed`, `show_if_slow`, `show_if_failed`, `delivery_over_cap`, `linked_mark_failed`. See [Home Notices](../home_notices.md#events). |
| UI profile `:blocking_notice` | HTTPS external links only, no primary button. Used for blocking notices. |
| `CommandTower::Services::HomeNotices::Deliver` | Pushes a `Delivery` notice to one user, optionally linked to an inbox item. |
| Built-in `ct.update_app` campaign | Active when `config.home_notices.enabled` and `config.home_notices.update_app_campaign` are true. Set the latter false to turn it off. |
| Rake `command_tower:home_notices:prune` | Deletes ended notice rows idle for 180 days. Run through `CommandTower::HomeNotices::PruneEndedJob`. |
| Account purge | `Services::Auth::PurgeUserAssociatedData` also deletes the user's home notice rows. Audit rows are untouched. |

## Host actions

1. Bump gem to `0.24.0` (or `>= 0.24.0`) and run `bundle install`.
2. **Run the migrations** (`db:migrate`) before the new code serves traffic. Both are additive.
3. **Grant the entities explicitly.** `me_home_notices` is not part of `member`; `admin_home_notices_kill` is never auto-granted. RBAC fails closed, so a user without the grant gets `403`. `owner` (`entities: true`) holds both. The dummy app's `home_notices_reader` group in `rails_app/config/rbac_groups.yml` is an example ([RBAC bootstrap](../bootstrap/09-rbac.md)).
4. To adopt: list notice classes in `config.home_notices.notices`, then set `config.home_notices.enabled = true`.
5. **Schedule the prune.** The gem schedules nothing. Run `command_tower:home_notices:prune` daily from the host scheduler, or enqueue `CommandTower::HomeNotices::PruneEndedJob`. See [Optional bootstrap](../bootstrap/13-optional.md#home-notices-prune).
6. Know the kill switch runbook before enabling: [Kill switch runbook](../home_notices.md#kill-switch-runbook).

## `secret_key_base` note

A blocking notice stores an HMAC-SHA256 content hash of the document it showed, keyed from `secret_key_base`. Rotating `secret_key_base` makes stored hashes unverifiable, so users who already acknowledged a blocking notice may see it again. Plan rotations accordingly.

## Rolling deploy

Migrate first, then roll the app. Old nodes do not know the tables or routes. Do not enable `config.home_notices.enabled` until every node runs 0.24.0.

## Also in this release

The platform commits between tag `0.23.0` and this release are the Home Notices slices only. The lane-ready Makefile (`.env.run` include, env ports, `make spec` / `make rubocop`) and the earlier UI foundation and message-definition work (`#61` to `#63`) were already described in 0.23.0 or touch only the repo's own tooling; no further host-visible change is known.

## Not in this release

- No scheduler inside the gem (hosts schedule the prune).
- No change to authentication, sessions or CSRF.
