# Upgrade: CommandTower 0.23.0

**From:** `0.22.0`  
**To:** `0.23.0`

Minor release: hosts can register a `MessageDefinition` per notification type. A defined type declares facts, an inbox composer, an email composer and slots, and gets inbox, email, push, SMS and Pushover from one source. Email carries a compliance footer and RFC 8058 one-click unsubscribe. The admin Message gallery previews every channel and can send a test email. Authoring: [ui.md](../ui.md), [messaging_integration_guide.md](../messaging_integration_guide.md).

Undefined types keep their current behavior except for the eight approved changes below.

## Changes that also affect undefined types

| # | Change | Host impact |
|---|--------|-------------|
| 1 | Impersonated Open (`POST /me/inbox/:id/open` while impersonating) no longer marks the item viewed and does not audit. | Returns the same detail. A non-impersonated Open still marks viewed. |
| 2 | `messaging_inbox_item_viewed` audit event, once per first view of an inbox item, for every type. | New audit rows (retention `ninety_days`). Enablement is configurable ([audit.md](../audit.md)). |
| 3 | `Cache-Control: no-store` on inbox list, show, open and conversation. | Nothing in CommandTower or the shared frontend relies on ETag or conditional GET for these routes. Check any host proxy or client that does. |
| 4 | `GET /me` returns a real `lastKnownTimezone`. | The column is now written (see `X-Time-Zone` below). Hosts with `/me` serializer or snapshot tests see a value instead of null. |
| 5 | Email colours can change (ERB and auth mailers) once a host adds `config/ui_tokens.json`. | Without that file nothing changes. With it, the 9 legacy `email_theme` keys derive from the file's palette. When the palette equals the host's `email_theme`, the derived keys are identical. |
| 6 | Frontend `impersonating` text changes from the `••••••` mask to "Open the app to check in" (arrives with `@commandtower/frontend` 0.3.0). | Visible to operators who impersonate. |
| 7 | `inbox_document_composer` deprecation log line at boot, for every type still using it. | Noisy and harmless; fires for both current hosts. Migrate to `message:` when ready. |
| 8 | `Open` renders the document once. The communication persister writes NULL (not `{}`) for the new columns of undefined types. | Response bodies are byte-identical for undefined types (regression specs). |

## Host-visible additions

| Change | Host impact |
|--------|-------------|
| `MessageDefinition`, `AnnouncementDefinition` | Register with `message:` on a notification type. Sealed at boot; invalid definitions fail the boot check. |
| Migration `AddMessageDefinitionColumnsToMessagingCommunications` | Adds nullable `slots` (JSON), `render_zone` (string, 64) and `metadata_version` (integer) to `messaging_communications`. Additive and reversible; no backfill, no index. |
| `config.messaging.strict_definitions` | Default true in development and test, false in production. True: a definition violation fails the request. False: logged and degraded. |
| `config.messaging.compliance` | `api_base_url` (or ENV `COMMAND_TOWER_API_BASE_URL`), `preferences_path`, `postal_address` (required for promotional definitions), `unsubscribe_secret`. See [messaging integration guide](../messaging_integration_guide.md#email-compliance-defined-types). |
| One-click unsubscribe | Unauthenticated `POST` and `GET /api/messaging/unsubscribe?token=`. Defined, eligible types only. |
| `X-Time-Zone` request header | Read by the HTTP boundary; written to `users.last_known_timezone` after a 2xx authenticated, non-impersonated request (at most once an hour per user). |
| `token` filtered parameter | The engine adds `:token` to `filter_parameters`, so Rails logs hide it. |
| Shared email token file | Optional host `config/ui_tokens.json` (from the frontend `ct-export-email-tokens` bin). An invalid file is a boot error; a missing file logs one warning. |
| Message gallery | `GET /admin/messaging/gallery`, `GET /admin/messaging/gallery/:notification_type_key`, `POST .../test-send`. Admin tool `messaging_gallery`. |
| Audit events | `messaging_unsubscribed`, `messaging_inbox_item_viewed`, `messaging_gallery_test_sent`. |
| Email text part | `UI::Email::TextPart` now renders links and buttons as `label: url`. This changes the plain-text part of every UI-document email, not only defined types. |
| UI library | `zone: :user`, `profile: :message`, `UI::Redaction` (impersonators never receive `code.value`), `UI::RequiredFacts::Verdict`, `Fragments::Markdown` (adds the `kramdown` runtime dependency). |

## Host actions

1. Bump gem to `0.23.0` (or `>= 0.23.0`) and run `bundle install` (new dependency `kramdown`).
2. **Run the migration** (`db:migrate`) before the new code serves traffic. The columns are nullable and additive.
3. **CORS:** if the host lists CORS `headers:` explicitly, add `X-Time-Zone` (and keep `X-UI-Catalog`). `headers: :any` already covers both. Frontend 0.3.0 sends `X-Time-Zone`, so a host adopts FE 0.3.0 only after its CORS list is checked ([bootstrap step 11](../bootstrap/11-auth-client-path.md)).
4. **Grant the two new entities explicitly.** `admin_messaging_gallery` (preview) and `admin_messaging_gallery_test_send` (test email) are never auto-granted to an admin role. RBAC fails closed for a controller no role maps, and `owner` (`allow_everything`) adds no guards, so until a host grants **both** entities to at least one role, every caller (owner included) gets `403` on the gallery routes. Add both grants to a host role ([RBAC bootstrap](../bootstrap/09-rbac.md)); the dummy app's `messaging_gallery_operator` group in `rails_app/config/rbac_groups.yml` is an example.
5. **Before enabling one-click unsubscribe headers (set `api_base_url`), scrub `token=` at the edge.** The token is in the query string, so load balancer, CDN and proxy access logs and error trackers (request URLs, breadcrumbs) record it. Configure the scrub there; it is outside this repo. Rails logs already hide `token`.
6. If hosts sit behind a load balancer, configure `trusted_proxies` so the unsubscribe per-IP limit sees client addresses.
7. Optional: add `config/ui_tokens.json` (change 5 above), set `config.messaging.compliance`, and register definitions.

## Rolling deploy

Migrate first, then roll the app. Old nodes ignore the new columns and never write them. New nodes can serve inbox reads for rows written by old nodes (NULL columns mean undefined behavior). During the roll, an unsubscribe link in an email sent by a new node can reach an old node, which has no `/messaging/unsubscribe` route and answers `404`; the link works once the roll finishes. Do not set `api_base_url` until every node runs 0.23.0.

## Accepted risks and known gaps

- **Unsubscribe replay (O1, accepted).** The token is a signed bearer value valid 90 days and is not single use. A forwarded or old link can turn email off again after a user re-enabled it. The effect is limited to email off for one type, which the user can re-enable. A preference-version binding was considered and not adopted.
- **"Message gallery" card without a screen.** Callers holding `admin_messaging_gallery` (once a host grants it, see host action 4) see the `messaging_gallery` tool card in the Admin workspace, but the route `/admin/messaging/gallery` does nothing until a host mounts the frontend screen (a later host set). Hide it with a host-side tool override if needed.
- **Closeout (not in this repo):** the `X-Time-Zone` note in `workspace_pickem_v4/artifacts/COMMANDTOWER_LOCAL_JOIN.md` is added by hand at release closeout.

## Not in this release

- No change to `announcement_produced` auditing.
- No per-type pause, add-to-calendar, device identity, or support re-render.
- No change to authentication, sessions or CSRF.
