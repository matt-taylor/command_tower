# Upgrade: CommandTower 0.22.0

**From:** `0.21.1`  
**To:** `0.22.0`

Minor release: adds the server-driven UI document library (`CommandTower::UI`) and reads the `X-UI-Catalog` request header into execution context. No HTTP response, route, or Inbox contract changes. Authoring reference: [ui.md](../ui.md).

## Host-visible changes

| Change | Host impact |
|--------|-------------|
| `CommandTower::UI` | New pure-Ruby library: primitives, tokens, Builder DSL, `Composer`, `Fragment`, five platform fragments, `TimeFormatter`, `Limits`, `Hardening`, `LegacyMapping`, and `Email::Renderer`. Nothing calls it from the engine yet. |
| `config.ui.image_hosts` | Image and avatar `src` must be https on an exact host in this list when a document is validated. Only matters if the host builds documents. |
| `X-UI-Catalog` header | Parsed by the HTTP boundary (missing or invalid is `1`, higher numbers clamp to the engine catalog) into `CommandTower::Current.ui_catalog`. Nothing reads it for authorization or response shape. |
| `tzinfo` | Runtime dependency (`~> 2.0`) used by the time formatter. |

## Host actions

1. Bump gem to `0.22.0` (or `>= 0.22.0`).
2. **No new migration.**
3. If a host lists CORS `headers:` explicitly, add `X-UI-Catalog`. `headers: :any` already covers it. See [bootstrap step 11](../bootstrap/11-auth-client-path.md).
4. Set `config.ui.image_hosts` only if the host will compose documents with images.

## Not in this release

- No new HTTP routes.
- No change to Inbox `content` (`inbox_document_v1`); `GET /me/inbox` bodies are identical with and without `X-UI-Catalog`.
- `LegacyMapping` and the email renderer are not wired into messaging or any response.
- No authorization or RBAC changes.
