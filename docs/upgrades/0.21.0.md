# Upgrade: CommandTower 0.21.0

**From:** `0.20.0`  
**To:** `0.21.0`

Minor release: member notification preferences expose a channel catalog, per-destination state, and ordered push settings, and preference PATCH merges onto stored member state. Legacy `urgency` and `sound` blocks remain. Push delivery and Inbox behavior are unchanged.

## Host-visible changes

| Change | Host impact |
|--------|-------------|
| Preference GET / PATCH payload | Each settings-visible notification includes `channelCatalog` (`key`, `label`, `description`, `order`, `glyphKey`), `destinations` (`state`, `effective`, `reasonCode`, `reason`), and `settings` (`single_select` rows). `urgency` and `sound` blocks stay. |
| Channel catalog | Platform channels carry presentation copy: Inbox, Email, SMS, Push, Pushover (`description`, `order`, `glyphKey`). |
| `settings` | When Push is a destination, urgency and sound project as ordered `single_select` rows. Option labels and descriptions are server-owned. Sound options use catalog labels. |
| Preference PATCH | Partial bodies merge onto stored member state. Omitted `channels`, `inbox`, `urgency`, and `sound` are preserved. Validation still runs before any write. |
| `destination_locks` | Optional notification declaration (`forced_on` / `forced_off` per destination). Applied after the merge. Defaults to `{}`. Cannot force off a mandatory destination. |
| `corrections` | Present only when the member explicitly submitted a destination boolean that the server corrected (locks or mandatory required). Omitted keys do not emit corrections. |

## Host actions

1. Bump gem to `0.21.0` (or `>= 0.21.0`).
2. **No new migration.** Run `bundle exec rails db:migrate` only if other pending host migrations exist.
3. Clients that render notification settings should read `channelCatalog`, `destinations`, and `settings`. Existing `urgency` / `sound` consumers keep working.
4. Set `destination_locks` on a notification declaration only when a destination must stay forced on or off.

## Not in this release

- No new HTTP routes.
- No Inbox document or rendering changes.
- No push execution, Expo, or email retry changes.
- No change to preference PATCH keys (`channels`, `inbox`, `urgency`, `sound`).
